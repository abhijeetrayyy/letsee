# How the redesign reaches every page

The plan for carrying out `RETHINK.md` and `PAGES.md` across all 37 routes, the new ones, and every instance of every component, without the app ever looking half old and half new, and without drifting back afterwards.

**The problem it solves.** Today about 3,100 colour decisions, 143 hard-coded font sizes, 29 content widths and 13 icon libraries are written inline in roughly 170 files (`00_current_state.md` §2). A redesign done page by page would repaint those by hand and start drifting again with the next feature. So this plan changes the *mechanism* first, then the *look* in one step, then the *structure* one family at a time, and fences each step with a test that fails if anyone goes back.

**The principle** (research/05 §8): separate three kinds of change.

| Kind | What changes | How it ships | How it's proven |
|---|---|---|---|
| Mechanical | class names, imports, component wrappers — not pixels | codemods, in bulk | screenshots show **zero** difference |
| Visual | token *values*: colour, type, space, radius, motion | **one** deploy | every route changes at once, because no route owns a colour any more |
| Structural | page order, navigation, logging | one page family at a time, behind a short-lived flag | the family's checklist (§5) |

## 0. Decisions made while building

Recorded as they were made, so this plan stays true to the code.

- **The token source is `src/design/tokens.css`**, a Tailwind `@theme` block, with `src/design/tokens.ts` as a hex mirror for JavaScript. The W3C JSON file and its build step were dropped: one hand-edited CSS file is simpler and the contrast test reads it directly.
- **Phase 1 names tokens by role and keeps every old value exactly.** Surfaces are `page`, `raised`, `overlay`, `hover`, `active`; borders `line`, `line-strong`, `line-input`; the primary fill `action` with `on-action` text; emphasis `accent`; focus `focus`. Text keeps its old steps as `ink-0` … `ink-950` so the rename is exact; phase 6 folds them into four names once the values already match.
- **The icon swap moved from phase 1 to phase 4**, because replacing icons changes pixels and phase 1's gate is "no visible change".
- **The film's light is drawn in CSS** from a small blurred copy of the poster, instead of a stored hue. That needs no migration, no backfill (the backfill route was removed in an earlier commit), and no server work. Migration 103 is therefore not needed for title pages; it returns only if share images need the light.
- **Film and series pages may run to 5 phone screens, not 4** (owner, 4 Oct 2026: "do whatever best option you find"). The extra screen is the image-led hero and the poster rows the third pass asked for; what cutting it would cost is content — cast, related titles, the glance. Measured signed out at 375 × 812 with folds closed: films 3.5–4.1 (Inception 4.1, The Dark Knight 3.9), series 4.4–4.6 (Breaking Bad 4.4, Game of Thrones 4.6). Episode (≤ 3) and profile (≤ 4) budgets are unchanged.
- **Screenshots cover signed-out routes only for now** (`npm run design:screens`, `npm run design:diff`), against the dev server with the installed Chrome. Signed-in fixture mode is still to build; until then the owner checks signed-in pages by hand.
- **Phase 3 built only what the flip needed.** The stylesheet lost 48 unused component classes and its colour literals; the surviving classes (`btn-*`, `glass-card`, `pill-glass`, `nav-*`…) read tokens. The new pieces (stub, pass card, tab bar, rooms, log sheet) are built inside the phase 5 step that first uses them, so nothing exists without a call site.
- **Phase 4 also:** set `h1` and `h2` in Newsreader through one base rule (and moved 112 bold titles to medium weight); made `tokens.css` an `@theme static` block, because Tailwind drops theme variables no utility class uses and the stylesheet reads several through `var()`; turned avatars into neutral monograms; removed 22 decorative rails beside headings, the blurred orbs behind the auth forms, and background blur inside scrolling content; and removed `react-icons` from the project (an ESLint error now stops it coming back).
- **The fonts never loaded until phase 5.** `next/font` put its variables on `<body>`, while Tailwind declares `--font-sans`, `--font-mono` and `--font-display` on `:root` and resolves `var()` there — so all three were empty and every page used the system font. Headings only looked right because the base rule names Newsreader directly. The variables now sit on `<html>`; Geist, Geist Mono and Newsreader all render.
- **The shell lives in `src/components/ds/`** (`Shell`, `tabs`, `Mark`, `AccountMenu`). Settings, lists, import, your data, country and sign-out moved into one account menu: from your face on a desktop, from the settings button on your own profile on a phone (where people look for it). The footer's TMDB credit moved there with it. The tab links do not prefetch: five uncacheable tabs on every page view would be five function invocations; the link wrapper's touch-intent prefetch is enough.
- **Rooms are read in the browser, from what is already stored** (`src/lib/db/rooms.ts`): messages, the viewings in your diary that name them, and passes both ways, under the viewer's own row-level security. `/app/people` prerenders as a static page, so the People tab costs no server work. `room_timeline` (one RPC instead of several reads) waits until rooms are the default.
- **Up next is the watchlist under its new name** until step 6 rebuilds it; **Log it** in the bars opens Quick add until the log sheet learns its search-first mode.
- **Found while building:** every page load, signed in or out, fetched `/api/user/providers` only to read the account's region — a guaranteed 401 and a function invocation for every anonymous view. The region now arrives with the auth snapshot, which already reads that row.
- **"Your people" is ranked in the browser, not by the nightly job.** The People tab already reads every input closeness needs (co-viewings, passes, messages, follows), so ranking there costs nothing; the nightly job would have meant a schema change and a write per user per night for the same answer.
- **A pass is a title card in a message.** 097's trigger already records every card as a pass, so *Pass to…* inserts one message per person and needs no new table or route. The room shows the card once, carrying the pass's state.
- **Migration 106 was dropped.** "Not for me" uses the pass's existing `dismissed_at` (the giver's views treat it as still open), and the thank-you is an ordinary message in the room with the rating pre-filled. 097's trigger already tells the giver once when the pass is watched. No production schema change was needed for step 6.
- **Opening People marks notifications read.** With the bell gone, People is where they are seen; otherwise the white dot could never clear.
- **Phase 6 tightened one ratchet rule.** `offWidths` exists to catch page content widths outside read, sheet and app; it now lets a single element's cap from the spacing scale up to 20rem through (a tooltip's `max-w-55`, a chart bar's `max-w-6.5`) while anything wider written on the spacing scale (`max-w-350`) still counts.
- **The phase 6 sweep found two things the redesign would have lost:** blocking and reporting someone (only the old profile's menu called those routes) and the followers and following lists. Both are back on the new profile. A route-caller test is what surfaced them, which is the argument for keeping it.
- **The invited door is `/invite?from=…`, not `/p/[token]`.** A room invite carries nothing private — a name and a face — so it needs no token and no table, and with the person in the query the page is static instead of a server render per view. Migration 108 (`share_links`) is still needed for the kinds that point at private things (a pass, a stub); those will use `?t=` on the same page.
- **Poster placeholder:** the light `no-photo.webp` glared on graphite; every reference now uses `public/no-photo.svg` (graphite with a quiet frame). The old file stays for anything cached. Small avatars (under 28 px) show one initial, because two overlap into noise in a group of faces.

## 1. Phases and their gates

Each phase ends with a gate: a test that turns red if the phase is undone. Nothing in a later phase starts until the earlier gate is green.

### Phase 0 — Count everything, and freeze it

1. **Inventory script** `scripts/design-inventory.mjs` writes `docs/design/inventory.json`: per file, the count of raw colour classes, hex/rgb/oklch literals, arbitrary pixel values, `max-w-*` variants, radius variants, `react-icons` imports, `<img>`, `<button>`, `outline-none`, `animate-*`. The numbers in `00_current_state.md` are its first run.
2. **Route manifest** `src/design/routes.ts`: every route → its family (`SYSTEM.md` §10) → its fixture name. Generated from `find src/app -name page.tsx`, then hand-checked.
3. **Fixtures.** Screenshots need the same data every time, signed in. Add `LETSEE_FIXTURES=1`: server fetches to TMDB read JSON from `tests/fixtures/tmdb/`, and the Supabase client is pointed at the local PostgreSQL built from `000_baseline.sql` plus migrations (the harness used to validate 095–102), seeded with a fixture user, five friends, a co-logged viewing, a recommendation, a series in progress, a private profile, a Hindi-titled film, a 60-character name and a title with no poster.
4. **Screenshots.** Add Playwright. One spec walks the manifest at 375 × 812 and 1280 × 800, signed in as the fixture user, animations off, timestamps masked. Commit the baselines. Add `@axe-core/playwright` (WCAG 2 A/AA) and store today's violation counts.

**Gate:** `tests/invariants/design-ratchet.test.ts` re-runs the inventory and fails if any count goes **up**. `tests/invariants/routes-have-families.test.ts` fails if a `page.tsx` is missing from the manifest.

### Phase 1 — Install the semantic layer, at today's values

1. Write `src/design/tokens.json` (W3C design-token format): primitives, then the semantic names from `SYSTEM.md` §1–§5, **each pointing at today's value** (`bg` = `#09090b`, `text-3` = `#71717a`, the primary button = today's `#22c55e`…). Declare every allowed text/background pair.
2. A build step writes `src/design/tokens.css` (OKLCH, with a hex copy of each colour for places OKLCH can't go: share images, `theme-color`, the manifest). `globals.css` imports it into `@theme`.
3. **Codemod** `scripts/codemods/semantic-classes.mjs` rewrites class strings: `bg-surface-950` → `bg-bg`, `bg-surface-900/60` → `bg-bg-raised`, `text-surface-500` → `text-text-3`, `text-white` → `text-text-1`, `border-surface-800` → `border-line`, `text-[10px]` → `text-label`, arbitrary spacing to the nearest step, `max-w-*` to `w-read` / `w-app` / `w-sheet`. The mapping table lives next to the codemod and is reviewed once. Anything it can't map confidently gets a `// design: manual` comment and is fixed by hand in a separate commit.
4. **Icon codemod** maps the twelve `react-icons` sets to Lucide equivalents by a reviewed table; unmapped icons are listed.

**Gate:** screenshots show zero difference (or reviewed sub-pixel noise) on every route at both widths. That proves the change was only mechanical.

### Phase 2 — Make drift impossible

Add invariants in the style of the existing `tests/invariants/` (each with a commented allowlist and a stored count that may only fall, reaching zero by the end of phase 6):

| Test | Fails when |
|---|---|
| `no-raw-colours` | a class names a Tailwind palette colour (`zinc`, `emerald`, `white/…`, `surface`, `brand`…) or a file outside `src/design/` contains `#hex`, `rgb(`, `oklch(` |
| `hue-means-something` | any hue outside the film-light and danger tokens appears in a component (the interface is graphite and white) |
| `no-arbitrary-values` | `-[…px]`, `-[…rem]`, `-[#…]` in a class string |
| `one-icon-family` | any import from `react-icons` |
| `ds-primitives-only` | raw `<button>`, `<dialog>`, `<input type="checkbox|range">` outside `src/components/ds/` |
| `focus-has-a-replacement` | `outline-none` without the focus utility |
| `motion-is-tokenised` | `duration-[…]`, `transition-[…]`, or an `animate-*` not in the token set; any infinite animation other than a spinner |
| `token-contrast` | any declared text/background pair is below 4.5 : 1, or a UI edge below 3 : 1 — so a later palette tweak cannot ship a failing pair |
| `widths-are-three` | a `max-w-*` other than the three width tokens |
| `every-family-has-a-skeleton` | a family template without a matching `loading.tsx` shape |

## 4. Cost guardrails

The redesign may not spend the cost discipline (`docs/incident-2026-08-23-deployment-paused.md`).

- **No new per-request server work.** Film lights are a stored hue; *your people* is computed nightly inside the existing taste job; a room's timeline is one RPC when someone opens it; the invited door is one cached read. Nothing runs per view that didn't before.
- **No new cron.** The Hobby plan allows two scheduled jobs and the app already has three in `vercel.json`; nothing here adds one.
- **No prefetch comes back.** research/02 notes the poster-to-page morph only plays on prefetched links; letsee turned eager prefetch off on purpose. The morph is therefore **not** used; title pages fade in instead.
- **Fonts:** ≈ 161 KB preloaded (Newsreader 132 + Geist 29), cached after the first visit; the italic and the mono load only where used.
- **Images:** TMDB sizes from `SYSTEM.md` §7; no Vercel image optimisation for TMDB art; nothing larger than w1280.
- **Nothing becomes crawlable.** Every new route (Up next, People, rooms, `/p/[token]`, `_ds`) inherits `noindex`, and robots.txt still disallows everything; the existing crawl invariant stays.
- **Screenshot CI runs in GitHub Actions or locally**, never against a Vercel deployment.

## 5. Definition of done

- [ ] **In the route manifest; renders its family template; draws no outer layout of its own.**

## 6. What this plan will not do

- Redesign one page by hand, ahead of the system, "to see how it looks". The board (published separately) is for that; code follows the phases.
- Ship two design systems side by side for longer than one family's flag.
- Leave a family half-migrated: the flag expiry test forbids it.
- Ship rooms before logging and titles are on the new system: rooms show stubs, passes and takes, so those come first.
- Introduce an animation library, a component library dependency, or a second icon set.
- Change behaviour the product already decided (no streaks, notifications only for what a person did, the private diary) to make a screen look fuller.
